# Claude session bots: design spec

This is the source of truth for the widget. If something here disagrees with your own taste, follow this file.

- `reference/*.png`: the target look. The labels there use Inter, but the project names use DejaVu Sans Mono as a stand-in for JetBrains Mono.
- `spritesheet.png` + `sprites.json`: every sprite. They are generated by `sprites.py`.
- All sizes are **logical pixels at 1×**. GTK multiplies them by the monitor scale.

---

## 1. What it is

A small always-on-top panel in a screen corner. Each running Claude Code session is a pixel-art robot. The robot's colour, face and a small indicator next to it show what that session is doing. The user should be able to read it at a glance without opening a terminal.

When there are no sessions, hide the panel completely.

## 2. States

| id | Label | Meaning | Robot frames | Indicator frames | Label colour | Project colour |
|---|---|---|---|---|---|---|
| `needs` | Needs you | Claude is blocked: permission prompt, question, or the turn failed | `needs-0` ↔ `needs-1`, 600 ms each | `bang-0` ↔ `bang-1`, 300 ms each | `#FF7A88` | `#9D98B1` |
| `done` | Finished | Turn finished, user hasn't looked yet | `done-0` (still) | `spark-0` ↔ `spark-1`, 450 ms each | `#FFC24D` | `#9D98B1` |
| `work` | Working | Claude is thinking or running tools | `work-0 → work-1 → work-0 → work-1 → work-2`, 500/500/500/500/150 ms; on `work-1` the robot also moves up 2 px | none | `#4FE08F` | `#9D98B1` |
| `idle` | Idle | Session open, nothing new | `idle-0` (still) | `zz-0` ↔ `zz-1`, 900 ms each | `#A7A3B6` | `#8A85A0` |

- Animation: use one 100 ms tick for the whole widget. Each cell picks its frame from the time since its current state began.
- Stop the tick when nothing on screen animates.
- Order: sessions keep a stable order, oldest session first. Don't reorder on state change: a robot's position helps the user recognise the project.
- Show at most 8 sessions. If there are more, the 8th cell becomes a "+N" cell (same 72 × 76 size, text "+N", Inter 16 px semibold, `#9D98B1`).

## 3. Sprites

- Sheet: `spritesheet.png`, 64 × 64 RGBA, transparent background. `spritesheet@2x.png` is the same sheet scaled ×2 with nearest-neighbour.
- Robots: 16 × 16. Indicators: 8 × 10.

| key | x, y, w, h | key | x, y, w, h |
|---|---|---|---|
| needs-0 | 0, 0, 16, 16 | bang-0 | 48, 0, 8, 10 |
| needs-1 | 16, 0, 16, 16 | bang-1 | 56, 0, 8, 10 |
| done-0 | 0, 16, 16, 16 | spark-0 | 48, 16, 8, 10 |
| work-0 | 0, 32, 16, 16 | spark-1 | 56, 16, 8, 10 |
| work-1 | 16, 32, 16, 16 | zz-0 | 48, 48, 8, 10 |
| work-2 | 32, 32, 16, 16 | zz-1 | 56, 48, 8, 10 |
| idle-0 | 0, 48, 16, 16 | | |

**`sprites.json` format:**

```json
{
  "sprites": {
    "<key>": {
      "x": 0,
      "y": 0,
      "w": 16,
      "h": 16,
      "rows": ["16 chars", "..."],
      "palette": {"o": "#5C1426"}
    }
  }
}
```

In `rows`, `.` is transparent.

**Rendering rules:**
- Widget scale is 2: one sprite pixel = 2 × 2 logical px. A robot is 32 × 32 and an indicator is 16 × 20.
- Notification icon scale is 3: 48 × 48.
- Nearest-neighbour filtering only. Integer positions only. Never blur or antialias the sprites.
- To change a sprite, edit `sprites.py` and run `python3 design/sprites.py design`. Never paint the PNG by hand.

## 4. Layout

### Panel

- Corner radius 12.
- Fill `rgba(21, 18, 29, 0.90)`.
- 1 px border `rgba(255, 255, 255, 0.08)`, stroked inset by 0.5 px.
- Optional shadow `0 8 24 rgba(0, 0, 0, 0.45)`. It needs 24 px of transparent surface around the panel; skip it if it complicates the input region.
- Inset 6 (1 px border + 5 px padding). Gap between cells 4.
- Horizontal: **W = 8 + 76n, H = 88**. n = 1 → 84 × 88; n = 4 → 312 × 88.
- Vertical: **W = 176, H = 8 + 48n**. n = 1 → 176 × 56; n = 4 → 176 × 200.
- Distance from the screen corner: 16 px from both edges.

### Horizontal cell: 72 × 76

Positions are relative to the cell.

| Element | Size | Position |
|---|---|---|
| Hover fill | 72 × 76, radius 8 | (0, 0) |
| Stage | 56 × 36 | (8, 4) |
| Robot | 32 × 32 | (20, 8); during the working bounce (20, 6) |
| Indicator | 16 × 20 | (48, 4), overlapping the robot's right edge by 4 px |
| State label | line box 14 high, centred horizontally | top at y = 43 |
| Project name | line box 13 high, centred, max width 68 px then "…" | top at y = 57 |

### Vertical row: 164 × 44

Positions are relative to the row.

| Element | Size | Position |
|---|---|---|
| Hover fill | 164 × 44, radius 8 | (0, 0) |
| Stage | 56 × 36 | (0, 4) |
| Robot | 32 × 32 | (12, 8), bounce (12, 6) |
| Indicator | 16 × 20 | (40, 4) |
| Text column | 100 wide, two lines (label 14 + project 13), centred vertically | x = 58 |

- Project names in the vertical row are cut at 100 px.
- Right padding is 6.

## 7. Interactions

### Hover

- The cell fills with the hover colour (radius 8). The robot keeps animating.
- A tooltip appears after 400 ms:
  - 232 wide, padding 10 / 12, radius 8.
  - Fill `#221D30`, 1 px border `rgba(255, 255, 255, 0.10)`, shadow `0 8 20 rgba(0, 0, 0, 0.5)`.
- Tooltip position:
  - Horizontal layout in a top corner: 6 px under the cell.
  - Horizontal layout in a bottom corner: 6 px above the panel.
  - Vertical layout: beside the panel, on the screen side away from the edge.
- Tooltip content, top to bottom, 4 px apart:
  1. Project name (left) and elapsed time (right): "just now", "waiting 2 min", "5 min ago", "working 1 min", "idle 40 min".
  2. 6 × 6 square in the state colour, then the state label.
  3. Message from the hook, for example "Claude needs your permission to use Bash". For the other states: "Done. Waiting for your next prompt.", "Running Bash: npm test" (tool name + short input), "Session open, nothing new".
  4. Path, with `~` for home.
  5. After a 1 px divider (`rgba(255, 255, 255, 0.08)`, 2 px margin above, 6 px padding below): "Click: open the terminal · Right-click: options".

### Click

- Left click focuses that session's terminal (see §10).
- A Finished session becomes Idle once clicked.

### Right-click menu

The menu opens at the pointer.

- Menu: 184 wide, padding 4, radius 10, fill `#1E1A2A`, border `rgba(255, 255, 255, 0.10)`, shadow `0 10 28 rgba(0, 0, 0, 0.55)`.
- Items: 28 tall, padding 0 8 0 6, radius 6, gap 8, a 14 px leading slot for check marks. Hover fill `rgba(255, 255, 255, 0.08)`.

Menu items:

1. **Move to corner ▸**. Opens a submenu that is 148 wide and overlaps the parent by 4 px. The submenu has Top left, Top right, Bottom left and Bottom right. The current corner has a check mark. Each item also has a 14 px corner glyph on the right: a rounded square outline with the matching corner filled.
2. **Vertical layout**: a check toggle.
3. **Notifications**: a 26 × 14 switch on the right.
4. A separator: 1 px, margin 4 6.
5. **Quit**.

A `Gtk.PopoverMenu` built from a `Gio.Menu` is acceptable if exact styling is impractical. Style it with CSS to get as close as possible.

### Settings

- Defaults: top right, horizontal, notifications off.
- Save to `~/.config/claude-session-bots/config.json`.

## 8. Notifications

Send a notification when a session **enters** Needs you or Finished. Don't send:

- for states that already exist at widget start-up,
- when notifications are switched off (the default),
- in `--demo` mode, whatever the switch says,
- the same transition twice.

| | Needs you | Finished |
|---|---|---|
| App name | Claude sessions | Claude sessions |
| Title | `<project> needs you` | `<project> is finished` |
| Body | hook message | Done. Waiting for your next prompt. |
| Priority | URGENT | NORMAL |
| Icon | `needs-0` at 3× (48 px PNG) | `done-0` at 3× |
| Button | Open terminal → focus terminal | same |

- Use `GNotification`. Install a `.desktop` file whose name matches the application id so the notification daemon or portal accepts it.
- The daemon draws the notification in its own style. The mockups on the design canvas are only a guide.

## 9. Where the states come from: Claude Code hooks

One hook script handles every event. It reads the event JSON on stdin and writes one file per session:

`$XDG_RUNTIME_DIR/claude-session-bots/sessions/<session_id>.json`

If `XDG_RUNTIME_DIR` is unset, use `~/.cache/claude-session-bots/sessions/`.

The file contains:

```json
{
  "session_id": "...",
  "state": "needs|done|work|idle",
  "project": "<basename of cwd>",
  "cwd": "...",
  "message": "...",
  "since": 1764000000.0,
  "updated": 1764000000.0,
  "claude_pid": 12345
}
```

`since` changes only when the state changes. `claude_pid` is the parent PID of the hook process.

### Event mapping

| Hook event | Resulting state |
|---|---|
| `SessionStart` | `idle` (the robot appears) |
| `UserPromptSubmit` | `work` |
| `PreToolUse`, `PostToolUse` | `work`; message "Running <tool_name>: <short input>" |
| `PermissionRequest` | `needs`; message "Permission needed: <tool_name>" |
| `Notification` with `notification_type` `permission_prompt`, `elicitation_dialog`, `elicitation_url_dialog` or `agent_needs_input` | `needs`; message = the event's `message` |
| `Notification`, any other type (for example `idle_prompt`) | no change |
| `Stop` | `done` |
| `StopFailure` | `needs`; message "Stopped: <error type>" |
| `SessionEnd` | delete the file |

### Hook script rules

- Write atomically: write a temp file, then rename it.
- Always exit 0 and print nothing.
- Finish in well under 100 ms. Use the Python standard library only.
- Register it as `"type": "command"` with `"async": true` for each event above, in the user settings `~/.claude/settings.json`, so it covers every project.
- Check field names against the current hooks reference before relying on them: https://code.claude.com/docs/en/hooks

### Widget side

- Watch the folder with `Gio.FileMonitor`.
- Also sweep every 30 s:
  - Remove a session whose `claude_pid` is gone.
  - Turn Finished into Idle after 10 min.

## 10. Platform notes (Fedora, Wayland)

### Niri (main session)

- Use **gtk4-layer-shell**: layer OVERLAY, anchored to the two edges of the chosen corner, margins 16, exclusive zone 0, keyboard mode NONE. Use ON_DEMAND only if the menu needs it.
- In Python, the library must be loaded before `gi` imports GTK:

  ```python
  from ctypes import CDLL
  CDLL("libgtk4-layer-shell.so")  # on Fedora it may be "libgtk4-layer-shell.so.0"
  ```

  `LD_PRELOAD` in the launcher also works.

### GNOME

GNOME doesn't support layer-shell. Detect that with `Gtk4LayerShell.is_supported()`. Then fall back to an undecorated normal window. The user sets it to Always on Top themselves (Alt+Space).

### Drawing

- Load the sheet once as a `Gdk.Texture`.
- Draw sub-rectangles with `Gtk.Snapshot.append_scaled_texture(..., Gsk.ScalingFilter.NEAREST, ...)` (GTK 4.10+), or with Cairo and `cairo.FILTER_NEAREST`.
- At monitor scale 2, one sprite pixel becomes 4 × 4 device pixels.
- Fractional scales may make a few pixels uneven. That's acceptable.

### Focusing the terminal on Niri

1. Run `niri msg --json windows`.
2. Find the window whose `pid` is an ancestor of `claude_pid`.
3. Run `niri msg action focus-window --id <id>`.

On other desktops, do nothing.

### Autostart

Use a systemd user unit bound to `graphical-session.target`, or a `spawn-at-startup` line in the niri config. Ask the user which.
